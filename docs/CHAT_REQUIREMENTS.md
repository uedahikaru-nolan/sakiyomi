# チャット機能 要件定義書

**文書作成日**: 2025-12-13
**バージョン**: 1.0
**ステータス**: 要件定義

---

## 1. 概要

### 1.1 目的
SAKIYOMIツールにおいて、ユーザーと運営者が1対1でコミュニケーションできるチャット機能を提供します。ユーザーは質問や相談を運営に直接送信でき、運営者は適切なサポートを提供できるようにします。

### 1.2 背景
- ユーザーからの問い合わせに迅速に対応する必要がある
- メールよりもリアルタイムなコミュニケーション手段が必要
- ユーザーサポートの質を向上させ、顧客満足度を高める

### 1.3 スコープ
**含まれる機能**:
- ユーザーと運営の1対1チャット
- リアルタイムメッセージング
- 未読メッセージ通知
- メッセージ履歴の保持
- フローティングチャットボタン

**含まれない機能**:
- ユーザー同士のチャット
- グループチャット
- ファイル添付（初期バージョン）
- 音声・ビデオ通話
- 既読ステータス（初期バージョン）

## 2. 機能要件

### 2.1 チャットルーム

#### 2.1.1 チャットルーム作成
- **要件ID**: CHAT-001
- **優先度**: 高
- **説明**: ユーザーごとに1つのチャットルームを自動作成
- **詳細**:
  - ユーザーが初めてチャットを開く際、自動的にチャットルームを作成
  - チャットルームは`chat_rooms`テーブルに保存
  - 各ユーザーは1つのチャットルームのみ所有可能
  - チャットルームには運営者（admin/super_admin）が参加
- **受入基準**:
  - ユーザーがチャットボタンをクリックした際、自動的にチャットルームが作成される
  - 既存のチャットルームがある場合は既存のものを表示
  - チャットルーム作成エラー時は適切なエラーメッセージを表示

#### 2.1.2 チャットルーム一覧表示（運営側）
- **要件ID**: CHAT-002
- **優先度**: 高
- **説明**: 運営者は全てのチャットルームを一覧表示できる
- **詳細**:
  - 最終メッセージ日時の降順で表示
  - 未読メッセージ数を表示
  - ユーザー名を表示
  - ページネーション対応（20件/ページ）
  - 検索・フィルタリング機能
- **受入基準**:
  - 運営者専用ページでチャットルーム一覧が表示される
  - 未読件数が正確に表示される
  - ユーザー名での検索が機能する

### 2.2 メッセージ送受信

#### 2.2.1 メッセージ送信
- **要件ID**: CHAT-003
- **優先度**: 高
- **説明**: ユーザーと運営者がテキストメッセージを送信できる
- **詳細**:
  - 最大文字数: 2,000文字
  - 改行対応
  - 空白のみのメッセージは送信不可
  - 送信時にリアルタイムで相手側に反映
  - メッセージは`chat_messages`テーブルに保存
- **受入基準**:
  - メッセージ送信が正常に完了する
  - 相手側画面にリアルタイムで表示される
  - バリデーションエラーが適切に表示される

#### 2.2.2 メッセージ受信・表示
- **要件ID**: CHAT-004
- **優先度**: 高
- **説明**: 送受信されたメッセージを時系列で表示
- **詳細**:
  - 時系列順（古い順）で表示
  - 送信者と受信者を視覚的に区別
  - タイムスタンプ表示（相対時間 + 絶対時間）
  - スクロール時に過去のメッセージを自動読み込み（無限スクロール）
  - 最新メッセージに自動スクロール
- **受入基準**:
  - メッセージが正しい順序で表示される
  - 自分と相手のメッセージが区別できる
  - 過去のメッセージをスクロールで読み込める

#### 2.2.3 リアルタイム更新
- **要件ID**: CHAT-005
- **優先度**: 高
- **説明**: Supabase Realtimeを使用したリアルタイムメッセージング
- **詳細**:
  - 新しいメッセージが送信されると即座に相手側に表示
  - WebSocketを使用した双方向通信
  - 接続断時の自動再接続
  - オフライン時は再接続時にメッセージを取得
- **受入基準**:
  - メッセージが1秒以内に相手側に表示される
  - 接続が切れても自動的に再接続される
  - 再接続後に未受信メッセージが取得される

### 2.3 UI/UX

#### 2.3.1 フローティングチャットボタン
- **要件ID**: CHAT-006
- **優先度**: 高
- **説明**: 画面右下に固定表示されるチャットボタン
- **詳細**:
  - 位置: 画面右下（bottom: 24px, right: 24px）
  - サイズ: 60x60px（円形）
  - アイコン: メッセージアイコン
  - 未読バッジ表示（未読数を赤丸で表示）
  - ホバー時のアニメーション
  - 全ダッシュボードページで表示
  - 認証済みユーザーのみ表示
- **受入基準**:
  - 全ページで右下に固定表示される
  - 未読件数が正確にバッジ表示される
  - クリックでチャットウィンドウが開く

#### 2.3.2 チャットウィンドウ
- **要件ID**: CHAT-007
- **優先度**: 高
- **説明**: チャット画面のUI
- **詳細**:
  - 表示方法: モーダル形式（フルスクリーンまたは右下ポップアップ）
  - サイズ:
    - デスクトップ: 400x600px（右下ポップアップ）
    - モバイル: フルスクリーン
  - レイアウト:
    - ヘッダー: タイトル、閉じるボタン
    - ボディ: メッセージ一覧
    - フッター: 入力欄、送信ボタン
  - レスポンシブ対応
- **受入基準**:
  - デスクトップとモバイルで適切に表示される
  - スクロールが正常に動作する
  - 入力欄が常に表示される

#### 2.3.3 入力エリア
- **要件ID**: CHAT-008
- **優先度**: 中
- **説明**: メッセージ入力フォーム
- **詳細**:
  - テキストエリア（自動リサイズ、最大5行）
  - Enterキーで送信（Shift+Enterで改行）
  - 送信ボタン
  - 文字数カウンター（残り文字数表示）
  - 送信中のローディング表示
- **受入基準**:
  - Enterキーで送信できる
  - Shift+Enterで改行できる
  - 文字数制限が正しく機能する

### 2.4 通知

#### 2.4.1 未読メッセージ通知
- **要件ID**: CHAT-009
- **優先度**: 中
- **説明**: 新しいメッセージの通知
- **詳細**:
  - フローティングボタンにバッジ表示
  - ブラウザ通知（ユーザーが許可した場合）
  - チャット画面が開いていない時のみ通知
  - 運営側ダッシュボードにも通知表示
- **受入基準**:
  - 未読メッセージがある時にバッジが表示される
  - ブラウザ通知が正しく表示される
  - チャット画面を開くと未読がクリアされる

### 2.5 運営者機能

#### 2.5.1 運営者ダッシュボード
- **要件ID**: CHAT-010
- **優先度**: 高
- **説明**: 運営者専用のチャット管理画面
- **詳細**:
  - パス: `/admin/chats`
  - チャットルーム一覧表示
  - 各ルームの詳細情報（最終メッセージ、未読数、ユーザー情報）
  - チャットルーム検索・フィルタ
  - メッセージ統計情報（総チャット数、未返信数など）
  - admin/super_adminロールのみアクセス可能
- **受入基準**:
  - 運営者のみアクセスできる
  - チャットルーム一覧が正しく表示される
  - 統計情報が正確に表示される

#### 2.5.2 チャットルームステータス管理
- **要件ID**: CHAT-011
- **優先度**: 低
- **説明**: チャットルームのステータス管理
- **詳細**:
  - ステータス: open（対応中）、resolved（解決済）、closed（クローズ済）
  - ステータスの変更機能
  - クローズ済みのチャットは別タブで表示
  - ステータス履歴の記録
- **受入基準**:
  - ステータスを変更できる
  - ステータスごとにフィルタできる
  - 履歴が正しく記録される

## 3. 非機能要件

### 3.1 パフォーマンス
- メッセージ送信のレスポンスタイム: 1秒以内
- メッセージのリアルタイム反映: 1秒以内
- チャットルーム一覧の読み込み: 2秒以内
- 同時接続ユーザー数: 100人以上対応

### 3.2 セキュリティ
- 認証済みユーザーのみチャット機能にアクセス可能
- ユーザーは自分のチャットルームのみアクセス可能
- XSS対策（メッセージのサニタイズ）
- CSRF対策
- SQLインジェクション対策

### 3.3 可用性
- 稼働率: 99.9%以上
- メンテナンス時間: 月次最大2時間

### 3.4 保守性
- コードの可読性とメンテナンス性を確保
- 適切なコメントとドキュメント
- エラーログの記録

### 3.5 スケーラビリティ
- ユーザー数の増加に対応可能な設計
- Supabase Realtimeの制限内での運用

## 4. データ設計

### 4.1 chat_rooms テーブル

| カラム名 | 型 | NULL | 説明 |
|---------|---|------|------|
| id | uuid | NOT NULL | チャットルームID（PK） |
| user_id | uuid | NOT NULL | ユーザーID（FK to users） |
| status | varchar | NOT NULL | ステータス（open/resolved/closed） |
| last_message_at | timestamptz | NULL | 最終メッセージ日時 |
| created_at | timestamptz | NOT NULL | 作成日時 |
| updated_at | timestamptz | NOT NULL | 更新日時 |

**制約**:
- `user_id`にユニーク制約（1ユーザー1チャットルーム）
- `status`にCHECK制約

### 4.2 chat_messages テーブル

| カラム名 | 型 | NULL | 説明 |
|---------|---|------|------|
| id | uuid | NOT NULL | メッセージID（PK） |
| chat_room_id | uuid | NOT NULL | チャットルームID（FK） |
| sender_id | uuid | NOT NULL | 送信者ID（FK to users） |
| message | text | NOT NULL | メッセージ本文 |
| is_read | boolean | NOT NULL | 既読フラグ |
| created_at | timestamptz | NOT NULL | 送信日時 |
| updated_at | timestamptz | NOT NULL | 更新日時 |

**制約**:
- `message`の長さ制限: 2000文字
- `created_at`にインデックス

### 4.3 chat_participants テーブル（将来拡張用）

| カラム名 | 型 | NULL | 説明 |
|---------|---|------|------|
| id | uuid | NOT NULL | ID（PK） |
| chat_room_id | uuid | NOT NULL | チャットルームID（FK） |
| user_id | uuid | NOT NULL | 参加者ID（FK） |
| role | varchar | NOT NULL | 役割（user/admin） |
| joined_at | timestamptz | NOT NULL | 参加日時 |
| last_read_at | timestamptz | NULL | 最終既読日時 |

## 6. API設計

### 6.1 チャットルーム取得・作成
- **エンドポイント**: `GET /api/chats/room`
- **認証**: 必須
- **説明**: ユーザーのチャットルームを取得（なければ作成）
- **レスポンス**: チャットルーム情報

### 6.2 メッセージ一覧取得
- **エンドポイント**: `GET /api/chats/rooms/[roomId]/messages`
- **認証**: 必須
- **パラメータ**:
  - `limit`: 取得件数（デフォルト: 50）
  - `before`: 指定ID以前のメッセージ取得（ページネーション用）
- **レスポンス**: メッセージ一覧

### 6.3 メッセージ送信
- **エンドポイント**: `POST /api/chats/rooms/[roomId]/messages`
- **認証**: 必須
- **リクエストボディ**:
  ```json
  {
    "message": "メッセージ本文"
  }
  ```
- **レスポンス**: 送信したメッセージ情報

### 6.4 未読メッセージをマーク
- **エンドポイント**: `PATCH /api/chats/rooms/[roomId]/read`
- **認証**: 必須
- **説明**: チャットルーム内の未読メッセージを既読にする

### 6.5 チャットルーム一覧取得（運営者用）
- **エンドポイント**: `GET /api/admin/chats/rooms`
- **認証**: 必須（admin/super_admin）
- **パラメータ**:
  - `page`: ページ番号
  - `limit`: 取得件数
  - `status`: ステータスフィルタ
  - `search`: ユーザー名検索
- **レスポンス**: チャットルーム一覧

## 7. 制約事項

### 7.1 技術的制約
- Supabase Realtimeの同時接続数制限
- WebSocketの接続制限
- データベース容量

### 7.2 ビジネス制約
- 初期フェーズでは1対1チャットのみ
- ファイル添付は次フェーズ
- 運営者の対応時間は平日10:00-18:00（表示）

---

## 8. リスクと対策

| リスク | 影響度 | 対策 |
|-------|-------|------|
| Realtime接続の不安定性 | 中 | 自動再接続機能、オフライン時のキューイング |
| スパムメッセージ | 高 | レート制限、メッセージ長制限 |
| 大量の未読メッセージ | 中 | ページネーション、自動アーカイブ |
| 運営者の対応遅延 | 中 | 自動応答メッセージ、営業時間の明示 |
